# 桌面客户端手工验证清单

自动化测试覆盖不到的东西：真麦克风、全局快捷键、托盘、系统权限、往别的窗口里输入文字。发版前、
或者改了这些地方之后，在真应用里照着点一遍。三个平台通用，平台专有的项标了出来。

每一行是「做什么 → 应该看到什么」。哪些项至今还没在哪个平台上点过，记在
[UX_REVIEW.md](UX_REVIEW.md) 第 5.2 节——点过之后请去那里划掉。

> 找别人帮忙测试（Windows + Android，自己搭服务）用的是另一份：[testing.md](testing.md)。

## 自动化测试管到哪儿

```bash
cd gui/stt-logic-tests && cargo test   # 不依赖 Tauri 系统库,任何平台都能跑
cd gui/src-tauri && cargo test         # 完整的客户端 crate
```

- `gui/stt-logic-tests` 用 `#[path]` 直接引用 `src-tauri/src/stt.rs`（不复制代码），覆盖 URL 构造、
  WebSocket 协议的序列化、分段和重传的逻辑。
- `gui/src-tauri` 的测试覆盖配置、快捷键解析、服务管理（用假服务跑「拉起 → 认领 → 停止」）、更新和
  建环境的决策逻辑。CI 在 Linux、macOS、Windows 上都跑，Windows 上还对着真进程验证进程识别。
- Linux 上编译完整的 crate 需要这些开发包：`pkg-config`、`libwebkit2gtk-4.1-dev`、`libgtk-3-dev`、
  `libsoup-3.0-dev`、`libjavascriptcoregtk-4.1-dev`、`libasound2-dev`、`libxdo-dev`。

## 开始之前

- 用**装好的应用**测，不要用 `npm run tauri dev`。macOS 上从启动台或访达打开，不要从终端启动
  （权限会记到终端头上，见 [macos-signed-build.md](macos-signed-build.md)）。
- 想从头走一遍首次启动：先退出应用，把配置文件挪走（位置见 [configuration.md](configuration.md)）。

## A. 首次启动和安装

| # | 做什么 | 应该看到什么 |
|---|--------|-------------|
| A1 | 没有配置文件时打开应用 | 出现向导，界面语言跟随系统，可以切换 |
| A2 | 向导里选「在本机跑模型」→「下载并安装」（机器上还没有仓库） | 有阶段和进度；装完路径自动填好，环境检查通过 |
| A3 | 同上，但机器上没有 git | 给出这个系统的安装命令，装好后「重新检测」能继续 |
| A4 | 点「启动服务」，模型还没下载过 | 主界面和设置里都能看到「正在下载模型… X / 约 Y」在动 |
| A5 | macOS：向导的权限那一步 | 三项权限逐项申请；授权后不用重启就生效，或者明确要求重启 |

## B. 录音和转写

| # | 做什么 | 应该看到什么 |
|---|--------|-------------|
| B1 | 按住快捷键说一句，松开 | 悬浮胶囊出现并显示音量；松开后文字出现在光标处 |
| B2 | 轻点一下（0.3 秒）/ 不出声按 5 秒 | 提示没听到声音，不报错误 |
| B3 | 连续说 60 秒、3 分钟 | 文字覆盖到最后一句；松手后只等最后一段 |
| B4 | 说到 5 分钟以上 | 有提醒；超出的部分截断，前面的照样转写 |
| B5 | 录音中按 Esc | 这一段被放弃，不输入任何文字 |
| B6 | 「录音方式」改成按一下开始、再按一下结束 | 两种方式都正常 |
| B7 | 录音中拔掉 USB 麦克风 / 断开蓝牙耳机 | 立刻提示，不会录下一段静音 |
| B8 | 服务没启动时按快捷键 | 不开始录音，胶囊提示未连接 |
| B9 | 模型加载中按快捷键 | 提示模型加载中 |
| B10 | 转写途中杀掉 STT 进程 | 几秒内报错，不会一直等 |
| B11 | 窗口隐藏时出错 | 胶囊或系统通知里能看到原因 |

## C. 快捷键

| # | 做什么 | 应该看到什么 |
|---|--------|-------------|
| C1 | 录制 Ctrl+Space、Cmd+Shift+X、F13；macOS 上再试 Option+A、Fn | 要么生效，要么当场说明不支持 |
| C2 | 中文输入法激活时、全屏应用里触发 | 正常触发，按键不会漏给输入法 |

## E. 服务管理

| # | 做什么 | 应该看到什么 |
|---|--------|-------------|
| E1 | 仓库路径填错 / `.venv` 缺依赖 / 端口被占 | 各自给出能照着做的原因；「环境体检」给出修复命令 |
| E2 | 终端里先起好服务，再在客户端点「启动」 | 被采纳，不重复拉起 |
| E3 | 强杀客户端后重开 | 认领还在跑的服务，能从界面停掉 |
| E4 | 应用内更新客户端 | 新版本启动后，两个服务显示为本应用启动的，不是「外部进程」 |
| E5 | 「更新服务」 | 拉取代码、重装依赖、重启服务，有进度；失败时原因可读 |
| E6 | 「切换服务代码的分支」再「切回 main」 | 两次都正常重启 |

## F. 模型和后处理

| # | 做什么 | 应该看到什么 |
|---|--------|-------------|
| F1 | 「STT 模型」下面那行说明 | 写的硬件和档位与这台机器相符，默认模型就是它说的那个 |
| F2 | 切到一个没下载过的大模型 | 有下载进度；加载完成之前不说「已切换」 |
| F3 | 断网时切换模型 | 失败原因可读，回到原来的模型；重启服务后加载的是上一个可用的模型 |
| F4 | 打开 LLM 后处理说一句 | 结果带标点、去掉了口头禅 |
| F5 | 转写途中杀掉 LLM 进程 | 返回识别的原文，并标明没有做后处理 |
| F6 | 非 Apple 平台：看 LLM 那一行 | 模型跑在 CPU 上时有提示；没有提示就是在显卡上 |
| F7 | 环境里没有 llama.cpp（非 Apple 平台） | 后处理开关置灰，旁边有「安装 llama.cpp」 |
| F8 | 词表里加一条热词和一条替换，说一句包含它们的话 | 都生效 |
