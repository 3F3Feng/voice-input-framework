# 用户体验审视与开发方案

> 审视基线:`fix/ux` 分支 `8254711`(已含「STT 模型加载失败不再永远显示正在加载」)。
> 日期:2026-09-22。

## 0. 怎么审的、审到哪儿

以一个**新用户**的身份把整条路走一遍:获取安装 → 首次启动 → 第一次说话 → 日常使用 →
改设置 → 出错排查 → 更新。对照的是用户在每一步**期待看到什么**,而不是代码写了什么。

覆盖范围:Tauri 客户端(`gui/src/App.vue`、`gui/public/indicator.html`、
`gui/src-tauri/src/*`)、Python 服务(`services/*`、`server/models/*`)、建环境脚本与 README。
Python 旧客户端(`client/`)只做定位层面的判断。

**这是一次代码走查,不是三平台真机点测。** 每条问题都标了证据等级:

- **已确认**:读代码能完整推出用户会遇到的现象;
- **疑似**:推理成立,但阈值或平台行为需要实测(第二阶段的验证矩阵专门覆盖这些)。

## 1. 用户旅程总览

| 阶段 | 用户期待 | 现在的样子 | 严重度 |
|------|----------|-----------|--------|
| 获取安装 | 下一个安装包就能用 | 安装包只是个壳:还得 clone 仓库、装 uv、建 Python 环境;README 的快速开始还是旧的 `pip install -r requirements-stt.txt`(那个文件无条件装 mlx,在 Linux 上建出来是坏的) | 高 |
| 首次启动 | 打开就能说话 | 默认是「远程连接」模式,去连一个不存在的 `127.0.0.1:6544` → 「未连接」;要自己找到 ⚙ → 服务 → 本地管理 → 启动 | 高 |
| 首次加载模型 | 知道要等多久 | 从 HuggingFace 下几百 MB 到几 GB,界面全程只有「已启动,正在加载模型...」;国内网络没有镜像选项 | 高 |
| 第一次说话 | 文字出现在光标处 | 「自动输入到窗口」默认关;窗口又常是藏着的 → 说完什么都没发生 | 高 |
| 日常使用 | 后台静默工作,出错能察觉 | 窗口隐藏时,错误只进看不见的 toast,胶囊直接消失;识别为空也不吭声 | 高 |
| 改设置 | 看得懂、改了就生效 | 模型只显示内部名;切换「成功」是假的也会说成功;提示词框打开时是空的 | 中 |
| 出错排查 | 日志里能看到原因 | Rust 侧的日志从没显示到界面上(见 F19) | 中 |
| 更新 | 点一下更新完继续用 | 装完直接退出,要自己重新打开;只更新了客户端,服务端不动 | 低 |

## 2. 第一阶段:功能缺失

按「用户能不能走完主流程」分四个里程碑。每条给出现状证据、要做什么、粗估工作量(S ≈ 1 天内 /
M ≈ 2–4 天 / L ≈ 1 周以上)。

### M1 让新用户能跑起来(首启与环境)

**F1 首次启动向导** · P0 · L
- 现状:`ServerMode` 默认 `Remote`(`gui/src-tauri/src/config.rs:26`),即使首启已经
  自动探测到了仓库(`lib.rs:962`),模式也还是远程;`local.auto_start` 默认关,所以
  即使切到本地,下次打开还得再点一次「启动」。
- 要做:首启检测到仓库 → 默认本地模式并勾上「随应用启动」;没检测到 → 进向导:
  ① 选本地 / 远程 ② (macOS)逐项授权并解释用途 ③ 环境检查(见 F2)④ 下载并加载
  模型(见 F4)⑤ 试录一句,确认文字能进目标窗口 ⑥ 选输出方式(见 F7)。

**F2 应用内建环境 / 环境体检** · P1 · M
- 现状:只有 `scripts/setup-env.sh`(bash),Windows 没有等价脚本;GUI 只检查
  「解释器文件存在」(`server_manager.rs` `path_report`),依赖缺了要到启动失败、翻日志
  才知道。
- 要做:「环境体检」按钮:uv 在不在、Python 版本、关键包能否 import、后端(MPS/CUDA/CPU)。
  缺什么就给一键修复(调 `setup-env.sh`,流式显示输出);补一个 PowerShell 版脚本。

**F3 合理的出厂默认值** · P0 · S
- 探测到仓库 → 本地模式 + 随应用启动;
- `ui.auto_input` 默认 `false`(`config.rs:212`)→ 改为首启时让用户选输出方式,不留一个
  「说了等于没说」的默认。

**F4 模型下载进度与镜像源** · P0 · M
- 现状:首次加载在服务里同步下载,界面只有一句「正在加载模型」(`server_manager.rs`
  `status()` 的 Starting 分支);整个仓库没有任何 `HF_ENDPOINT` / 镜像支持(只有给旧版
  Qwen 权重用的 ModelScope 脚本,和现在实际加载的 `mlx-community/*` 对不上)。
- 要做:服务端在 `/health` 报加载阶段与下载进度(已下载 / 总大小);界面显示进度条和
  预计剩余时间;设置里加「模型下载源」(HuggingFace / hf-mirror),以环境变量传给子进程。
- 依赖:R9(加载阻塞事件循环时 `/health` 根本答不上来,进度无从汇报)。

**F5 能看懂的模型选择** · P1 · M
- 现状:`/models` 的描述被写成 `"STT model: <model_id>"`(`services/stt_server.py:320`),
  而注册表里本来有中文描述和内存占用(`shared/model_registry.py`);GUI 只显示内部名
  `qwen_asr_mlx_native_small`;Linux / Windows 上照样列出只能在 Apple Silicon 上跑的
  MLX 模型;硬件推荐(`services/device.py` 的 `recommend_stt_model`)已经算出来了,
  却没告诉用户。
- 要做:`/models` 返回中文描述、内存、是否已下载、是否适配本机、是否推荐;下拉框按
  「推荐 / 可用 / 本机不支持(置灰)」分组;加「删除已下载模型」释放磁盘。

**F6 文档对齐** · P0 · S
- README 快速开始改为 `scripts/setup-env.sh`;模型表里的名字(`qwen_asr`、
  `whisper-small`)换成真实注册名;`shared/version_check.py` 的提示也还指向旧命令。
- 写清「从 Releases 下载客户端 + 本地建服务端」这条路径(现在 README 只讲从源码构建)。
- 明确 Python 旧客户端(`client/`、`run_client.py`)的定位:标为 legacy 或移除,
  别让新用户在两个客户端之间猜。

### M2 应用藏在后台时也能被感知(核心交互闭环)

**F7 输出方式** · P0 · M
- 现状:只有「自动输入到窗口」一种,用 enigo 逐字模拟键盘(`input.rs`),长文本慢;
  Linux 只开了 X11 后端(Wayland 下多半不可用,疑似);没有「只复制到剪贴板」。
- 要做:输出方式三选一:模拟打字 / 粘贴(写剪贴板 → 模拟粘贴 → 还原原剪贴板)/
  只复制。粘贴模式对长文本和输入法激活时更可靠。

**F8 后台反馈** · P0 · M
- 现状:转写失败时胶囊直接关掉(`lib.rs:255`),错误只进主窗口的 toast——窗口藏着时
  用户什么也看不到。说了话但识别出空文本时(比如只录到静音),客户端拿到的是空字符串,
  胶囊照样亮绿色、显示耗时,像成功了一样,然后什么都没发生(`App.vue` 的 `transcribe-done`
  遇到空文本直接跳过);只有完全没录到音频时才会报 `No speech detected`。
- 要做:胶囊增加「失败」「没听到声音」「未连接」三种状态,停留 2–3 秒并显示一句原因;
  窗口隐藏时再用系统通知兜底;可选开始 / 结束提示音。

**F9 托盘菜单** · P1 · M
- 现状:只有「显示窗口 / 退出」(`tray.rs`)。旧 Python 客户端的托盘有状态、当前模型、
  切换模型、检查更新、开机自启(`client/tray_manager.py:248-290`),迁移时丢了;
  前端监听着 `tray-check-update`(`App.vue:1468`),但没有任何地方发它。
- 要做:状态行(已连接 · 模型名 / 加载中 / 未连接)、最近一条结果(点击复制)、
  LLM 后处理开关、STT 模型子菜单、检查更新、设置;托盘图标随状态变化(空闲 / 录音 / 离线)。

**F10 macOS 再次打开应用没反应 + 单实例** · P0 · S
- 现状:macOS 上以 accessory 身份运行,没有 Dock 图标;`run()` 只处理 `RunEvent::Exit`
  (`lib.rs:1188`)。窗口隐藏时从启动台 / Finder 再点一次应用,什么都不出现。
  Windows / Linux 没有单实例保护(依赖里没有 single-instance 插件),双开就是两套快捷键
  监听,按一次录两遍。
- 要做:处理 `RunEvent::Reopen` → 显示主窗口;接入 `tauri-plugin-single-instance`,
  第二个实例把第一个的窗口叫出来然后退出。

**F11 录音控制** · P1 · M
- 现状:只有按住说话(macOS Caps Lock 例外)。录到 5 分钟上限时整段丢弃
  (`hotkey.rs:586`「这段音频未转录」),之前没有任何提醒。
- 要做:可选「切换模式」(按一下开始、再按一下结束),长段口述不用一直按着;
  录音中按 Esc 取消本次;到 4:30 时胶囊提示,到上限时截断转写,不丢弃。

## 3. 第二阶段:已有功能的鲁棒性

分两部分:3.1 是走查中**已经发现**的缺陷,可以直接修;3.2 是对每个功能做故障注入的
验证矩阵,用来发现走查漏掉的问题,并把疑似项坐实。

### 3.1 走查已发现的缺陷

#### P0:丢数据、结果错、假成功

**R1 长录音的后半段可能丢失** · 疑似(阈值需实测)
- 录音开始时建了容量 4096 的分块通道(`lib.rs:168`),但这个通道**要到松手后才开始被消费**
  (`run_transcription` 在 `stop` 之后才起);满了之后 `try_send` 静默丢块(`audio.rs:235`)。
  按 CoreAudio 默认每回调 512 帧 / 48 kHz 估算,约 44 秒后开始丢。完整音频其实还在
  fallback 缓冲里,只是流式模式下没用它。
- 修:录音开始就建 WS 连接,边录边传;或者改成无界 / 以 fallback 缓冲为准。

**R2 超过 5 分钟的录音整段丢弃**
- `hotkey.rs:586` 超时后 `reset()` 掉整段。修法见 F11(提醒 + 截断转写)。

**R3 STT 模型切换失败也提示「模型已切换」**
- `switch_stt_model`(`stt.rs:355`)不看 HTTP 状态;服务端 400 / 500 的错误体是
  `{"detail": ...}`,`server_message` 也读不到。同文件的 `switch_llm_model` 早已处理好,
  STT 这个漏了。
- 即便成功,`/models/select` 也只是「开始切换」,后台还要加载几秒到几分钟;界面立刻说
  「模型已切换」,头部立刻显示新模型名。应轮询 `/models/status/{name}` 到加载完成,期间显示
  「加载中」,失败时显示 `/health.error`。

**R4 保存提示词、拨 LLM 开关时,请求失败也报成功**
- `save_llm_prompt` / `set_llm_enabled`(`stt.rs:428`、`:451`)不检查状态码。LLM 服务没起时
  点「保存」,STT 回 502,界面仍弹「提示词已保存」。

**R5 切到一个坏模型之后,服务就没法用了,重启也恢复不了**
- `switch_model` 先释放旧模型再加载新的(`stt_engine.py:255`);模型选择在**加载成功之前**
  就写进了 `stt_state.json`(`stt_server.py:479`),下次启动会继续加载那个坏模型。
- 修:加载成功后才持久化;新模型加载失败时回滚到上一个可用模型。

**R6 快捷键录制:Ctrl+Space 会被存成单独一个 Ctrl**
- 录制用的是 `e.key`(`App.vue:1282`)。空格的 `e.key` 是 `" "`,拼出 `left_ctrl+ `;
  `parse_hotkey` 按 `+` 切分后把空白段过滤掉,剩下合法的 `left_ctrl`——于是之后每按一次
  Ctrl 都会开始录音。
- 同类问题:macOS 上 Option+字母的 `e.key` 是 `å` 这类字符,直接非法;Cmd 录得下来但
  解析不支持;应用失败的提示只有「更新失败」(`App.vue:1307`),不说原因。
- 修:改用 `e.code`;录完立即用后端同一个解析器校验并显示原因。

**R7 远程填 https 地址:能列出模型,但转写必失败**
- WS 地址只替换了 `http://`(`stt.rs:88`、`:254`),`https://` 原样交给 tungstenite,
  scheme 不受支持。应映射为 `wss://`。

**R8 LLM 后处理失败被静默吞掉**
- `call_llm_server` 失败时直接返回原文(`stt_server.py:222`、`:225`),客户端无从知道
  「这次没有经过后处理」。`result` 消息应带 `llm_error`,界面标注出来。

#### P1:卡住、误导、状态不准

**R9 MLX 模型的加载和推理都阻塞事件循环**
- Qwen MLX 在事件循环线程上同步加载(`stt_engine.py:125`,因为 Metal stream 绑线程),
  推理也是同步调 `generate`(`server/models/qwen3_asr_mlx_native.py:110`);`mlx_whisper` 和
  transformers 的推理同样是同步调用(`stt_engine.py:340`、`:365`)。
- 后果:首次下载模型的几分钟里 `/health` 不应答(F4 的进度根本报不出来);转写超过 1.5 秒时
  健康探测超时(`server_manager.rs` `HEALTH_TIMEOUT`),设置面板开着时「运行中」会跳成
  「启动中」,前端据此把连接置为断开(`App.vue:1409` 的 watcher),随后又弹「已连接」。
- 修:MLX 用一个专用的单线程执行器(加载和推理都在同一个线程上),不占主循环。

**R10 客户端的 HTTP / WS 请求全都没有超时**
- `stt.rs` 里每个请求都是 `Client::new()`(默认不设超时),`connect_async` 也没有超时。
  服务卡住时 `get_models` 会一直挂着,前端连接循环的「截止时间」形同虚设。

**R11 「已连接」的绿点只说明 `/models` 能通,不说明模型可用**
- `connectOnce` 能拉到模型列表就算连上(`App.vue:1102`),模型加载失败或还在加载时头部照样
  是绿点 + 模型名。加载失败后,每次录音都会触发一次重新加载,报错只剩一句
  `Failed to load STT model`(`stt_engine.py:307`),丢了真正的原因。
- 修:连接状态分「服务可达 / 模型就绪 / 加载中 / 加载失败」;转写报错带上 `load_error`。

**R12 连接状态不会自己更新**
- 只有设置面板开着、并且是本地模式时才轮询(`syncServerPolling`);远程模式从不轮询。
  服务挂了,头部仍显示已连接,要等按下快捷键说完一句才失败。
- 修:后台低频心跳(比如 15 秒一次)+ 失败后指数退避重连。

**R13 未连接时按快捷键照样录音,说完才报英文错误**
- 快捷键路径 `start_recording_internal`(`lib.rs:147`)不检查连接;按钮路径被 `:disabled`
  挡住了,快捷键路径没有。结果是说完才看到 `WebSocket connect failed: ...`,这段话白说了。
- 修:按下时先看连接和模型状态,不可用就在胶囊上直接提示、不开始录音。

**R14 外部启动、还在加载的服务会被当成「未运行」**
- `start()` 只认 `status == "ok"`(`server_manager.rs:1021`);`status()` 的 `(None, None)`
  分支(`:973`)把「端口有应答但在加载 / 加载失败」也报成未运行。用户在终端起了服务、正在
  加载时点「启动」,会再拉一个进程去抢端口。
- 修:`8254711` 里已有 `probe_raw`,改成按「端口有应答」来采纳和展示。

**R15 LLM 服务的 `/health` 分不出「加载失败」**
- 永远是 `loading`(`llm_server.py:419`),和 `8254711` 修 STT 之前是同一类问题;
  打开开关后要等满 30 秒才报「还在加载」,且超时分支不回收已拉起的进程(`lib.rs:588`)。
  非 Apple 平台上就会留下一个永远加载不完的 LLM 进程。

**R16 LLM 模型的选择会丢**
- 选择存在 STT 服务的 `stt_state.json` 里(`stt_server.py` `select_llm_model`),但 LLM 进程
  只读环境变量 `VIF_LLM_MODEL`,GUI 拉起时不传(`local.llm_model` 默认为空)→ 每次拨开关
  (停了再起)都回到默认的 Qwen3.5-4B-OptiQ。
- 另外,转发切换请求的超时是 30 秒;下载一个 4B 模型常常超过 30 秒,界面报「切换失败」,
  而 LLM 其实还在后台继续加载,最后换成功了,却没有被持久化。

**R17 配置的麦克风不在时静默改用默认设备**
- `select_device`(`audio.rs:447`)找不到就回落默认设备,不告诉用户;录音中设备断开只
  `eprintln`。蓝牙耳机断连后,可能是在拿笔记本内置麦克风录音,用户却不知道。

**R18 macOS 授予「输入监控」后快捷键不会自动恢复**
- 监听器只在启动时建一次,授权之后要重启应用,界面上没说(只对辅助功能提示了重启)。
  修:刷新权限时发现状态从「未授权」变为「已授权」,就重建监听器;不行就明确提示重启。

**R19 Windows 上自动探测仓库基本都会失败**
- `detect_repo` 只读 `HOME`(`server_manager.rs:1254`),Windows 上通常没有这个变量
  (应当用 `USERPROFILE` / `dirs::home_dir`)。

**R20 托盘创建失败被忽略**(疑似,依发行版而定)
- `let _ = tray::setup(app)`(`lib.rs:1018`)。Linux GNOME 在没有 AppIndicator 扩展时
  看不到托盘;再加上「启动时最小化」和「关窗只是隐藏」,应用既看不见也退不出。
  修:托盘不可用时不隐藏主窗口,关窗改为最小化。

**R21 Apple Silicon 上的 torch 是隐式依赖**
- `torch` 不在 Mac 的显式依赖里,现在是被 `mlx-whisper` 顺带拉进来的
  (`uv pip show torch` → `Required-by: mlx-whisper`),而 `services/device.py` 的 `detect()`
  每次加载模型都会 `import torch`,`switch_model` 也会。哪天 `mlx-whisper` 不再依赖 torch,
  Mac 上所有模型都加载不了。修:显式声明,或 MLX 路径不碰 torch。

#### 第二轮走查 + 实测新增(R31–R40)

这一批大多是在本机对真服务端实测坐实的(`say` 合成的 159 秒中文语音、真模型)。

- **R31** 子进程日志抽水线程遇到一行非 UTF-8 就退出,之后没人读管道,写满约 64 KB
  后 Python 服务阻塞在 write 上卡死(中文 Windows 上 Python 可能输出 GBK)。
- **R32** Windows 上拉起 `python.exe`、轮询 `tasklist` 都没加 `CREATE_NO_WINDOW`,
  会弹黑色控制台窗口。
- **R33** Windows 上认领遗留进程只看 pid 是否存活,重启后 pid 被复用时会把无关进程
  认成自己的,退出应用时 `taskkill /T` 连同进程树一起杀掉。
- **R34** 非 Apple 平台默认的 transformers Whisper:**说话超过 30 秒必然转写失败**
  (`ValueError: more than 3000 mel input features`)。实测坐实并已修。
- **R35** LLM 生成上限写死 256 token:159 秒口述(754 字)整理后被截断成 564 字,
  `success=True`。实测坐实并已修。
- **R36** 口述「帮我写一首关于春天的诗」,LLM 真写了一首诗,原话没了。实测坐实并已修。
- **R37** `/transcribe` 把任何上传文件都当 16 kHz PCM:44.1 kHz WAV、m4a 返回 200 + 空文本。
  实测坐实并已修。
- **R38** 主窗口「⌨️ 输入」按钮:点按钮时焦点在本应用自己身上,字全敲给了自己。
- **R39** 自动输入用模拟打字,文本里的换行会变成回车 —— 在聊天软件里等于提前发送。
  待 F7(粘贴模式)解决。
- **R40** `whisper_mlx*` 一句都转写不出来:给 `mlx_whisper.transcribe` 传了它不认的
  `return_timestamps`,每次 `TypeError`。实测坐实并已修。

R25(静音幻觉)和 R9(推理阻塞事件循环)也在这一轮实测坐实:3 秒纯静音被 Qwen 识别成
"The.";一段 2.4 秒推理期间 `/health` 探测超时。两者均已修,修后同样实测验证。
