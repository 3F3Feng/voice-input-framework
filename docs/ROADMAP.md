# 路线图

目标没变：一个**开箱即用**的语音输入工具——下载就能用，模型跑在自己的电脑上，桌面和手机都有。

这里只列方向和顺序。每一项的来龙去脉、哪些东西还没在真机上验证过，记在
[UX_REVIEW.md](UX_REVIEW.md) 第 5 节；每个版本实际做了什么，见 [CHANGELOG.md](../CHANGELOG.md)。

## 已经做到的

| 当初的目标 | 现在的状态 |
|-----------|-----------|
| 跨平台桌面客户端 | Tauri 客户端，macOS（Apple 芯片）/ Windows / Linux，应用内更新 |
| 精细的快捷键、托盘、悬浮提示 | 左右修饰键、Fn 键、按住或切换式录音、托盘菜单、悬浮胶囊 |
| LLM 后处理 | Gemma 4，提示词可改，带预设 |
| 不用装依赖，点开即用 | 向导里一键下载服务端并建环境（前提只剩 git）；模型按硬件自动选 |
| 中英文界面 | 跟随系统，可以手动切换 |
| 手机客户端 | Android 输入法和 iOS 键盘的初版，连自己电脑上的服务 |
| 非 Apple 平台的显卡加速 | NVIDIA 走 CUDA，AMD / Intel Arc 走 Vulkan，识别和后处理都跑在 llama.cpp 上 |

## 接下来

按顺序：

1. **客户端的测试版更新通道。** 现在测试者能在客户端里把服务端切到开发分支，但客户端安装包只能跟
   正式版。同时动了客户端和服务端的改动，只能发了正式版才在别人的机器上暴露问题。要做的是预发布版
   单独一份带签名的更新清单，加上设置里的「更新通道：正式 / 测试」。
2. **用真机数据校准硬件配置表。** 显存门槛、CPU 档的线程数门槛、后处理默认开不开的门槛，现在是按
   模型大小和一台 Mac 的测速外推的。需要 NVIDIA、AMD、Intel Arc 和纯 CPU 机器上的显存占用和延迟。
3. **没有 git 也能装。** 直接下载源码包；那样「更新服务」要另想办法。顺带处理境内访问 github.com
   慢时换镜像的问题（现在只能设环境变量 `VIF_REPO_URL`）。
4. **把还没在真应用里点过的东西点一遍。** 托盘、向导、剪贴板还原、历史、长录音、拔麦克风、崩溃后的
   提示；Windows 和 Linux 上的大部分界面。清单在 [rust-client-verification.md](rust-client-verification.md)。

小一些的：

- Whisper（transformers）自动检测语言时，结果里的语言一律报成 `en`。目前没有功能依赖它。
- iOS 没有免费的公开分发渠道：用免费 Apple ID 签名 7 天过期（现在有 `mobile/ios/renew.sh` 自动续）。
  AltStore 能不能正确重签「应用 + 键盘扩展 + App Group」还没试过。

## 还没排期的想法

来自最早的路线图，没有在做：

- 批量文件转写、说话人分离的界面（服务端已有 `/transcribe` 和 `/diarize` 接口）；
- 专业领域的词库、多人共享词表；
- 更多界面语言。

最早的路线图里还有云端识别 / 云端后处理和付费功能的设想。现在的定位是数据不出自己的设备，这些没有在做。
