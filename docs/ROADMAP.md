# 路线图

目标没变：一个**开箱即用**的语音输入工具——下载就能用，模型跑在自己的电脑上，桌面和手机都有。

这里只列方向和顺序。每一项的来龙去脉、哪些东西还没在真机上验证过，记在
[UX_REVIEW.md](UX_REVIEW.md) 第 5 节；每个版本实际做了什么，见 [CHANGELOG.md](../CHANGELOG.md)。

最近一次整体评估和重排：2026-10-12。

## 现在的状况

**做到了什么**

| 当初的目标 | 现在的状态 |
|-----------|-----------|
| 跨平台桌面客户端 | Tauri 客户端，macOS（Apple 芯片）/ Windows / Linux，应用内更新 |
| 精细的快捷键、托盘、悬浮提示 | 左右修饰键、Fn 键、按住或切换式录音、托盘菜单、悬浮胶囊 |
| 说完就出字 | 边录边识别：长口述松手后约 0.8 秒出结果（M3 Max）；RTX 4090 上 17 秒的话识别 0.4 秒、后处理 0.1–0.4 秒 |
| LLM 后处理 | Gemma 4，提示词可改，带预设；默认提示词按真实的识别输出调过，可以按模型各写一份 |
| 不用装依赖，点开即用 | 向导里一键下载服务端并建环境（前提只剩 git）；模型按硬件自动选 |
| 中英文界面 | 跟随系统，可以手动切换 |
| 手机客户端 | Android 输入法和 iOS 键盘的初版，连自己电脑上的服务 |
| 非 Apple 平台的显卡加速 | NVIDIA 走 CUDA，AMD / Intel Arc 走 Vulkan，识别和后处理都跑在 llama.cpp 上 |

**规模和节奏。** 客户端 Rust 约 2 万行、前端 5 千行，Python 服务约 8 千行，两个手机端加起来 5 千行；
Python 测试约 450 个、Rust 测试约 240 个，CI 在三个平台上跑。9 月 20 日到 10 月 6 日半个多月里发了
11 个桌面版本（2.2.0 → 2.7.2）和手机初版，三个多星期合了 34 个 PR。

**谁在用。** 仓库 1 个 star，从没有人提过 issue；最新的 2.7.2 安装包和更新清单加起来被下载了 24 次。
也就是说，现在是「维护者自己，加上几位帮忙测试的人」。

**三个问题，按要紧程度排：**

1. **做得比验得快。** [UX_REVIEW.md](UX_REVIEW.md) 5.2「还没在真机上验证的」已经有十三条，拆开是几十个具体的点：
   Windows 和 Linux 上的大部分界面、应用内更新后认领服务、硬件配置表的每一道门槛、llama.cpp 的
   Vulkan 版、手机端的长期使用……每发一版清单都在变长。Windows 那台开发机上没有 Rust 和 Node，
   改客户端只能靠 CI 编译（一轮半小时）；分开版本号的那次界面改动（PR #42）就是写完没法编译、没法看，
   只能等 CI 和别的机器。
2. **质量没有来自真实使用的数据。** 「后处理还是很差」这样的反馈落不到具体的句子上——拿不到当时
   说了什么、整理成了什么。10 月按识别输出的样子造了 200 例检查（`tools/llm_dictation_eval.py`），
   查出并修掉了两类毛病，但那是造的样本，不是谁真的说过的话；只在 Gemma-4-E4B 上量过。
3. **反馈渠道是空的。** 测试指南写了怎么反馈，没有人走 GitHub。问题都是维护者自己用出来、或者
   当面听来的。

所以接下来三个月的原则是：**先把已经做了的验掉、让质量看得见，再加功能。** 代码写得很快，
卡住进度的是真机上的验证和真实的反馈，这两样要人花时间，排计划时按它们来排。

## 接下来三个月

### 第一段：收尾，还债（10 月下半）

1. **把在途的合掉，发 2.8.0。** 客户端和服务端分开版本号（PR #42，合并前要在能跑应用的机器上看
   一眼「服务版本」那一栏）、Gemma-4-E2B 上验证新提示词、三个预设按新检查重调。2.8.0 是第一个
   按新规矩发的版本：两边各有各的更新记录，「更新服务」之前看得到这次换了什么。
2. **在自己的两台机器上把清单走一遍。** M3 Max 和 RTX 4090 的 Windows，照
   [rust-client-verification.md](rust-client-verification.md) 一项项点：托盘、向导、剪贴板还原、
   历史、长录音、拔麦克风、崩溃后的提示、应用内更新后认领服务、`setup-env.ps1`、环境体检。
   5.2 里能在这两台机器上验的，验一项划一项。
3. **让 Windows 那台机器能编译客户端**（装 Rust 和 Node），并把 `cargo fmt --check` 和 clippy
   放进 CI——现在它们只在本地的提交钩子里，没装钩子的机器上等于没有。

做完的标志：2.8.0 发出；5.2 的清单比现在短一半；在 Windows 上改一行客户端代码，本地就能跑测试。

### 第二段：让质量看得见（11 月）

4. **「这条整理得不对」。** 历史里已经存着每一条的识别原文和最终文字，结果也能改。差的是：改过的
   那一条把「模型整理成了什么」盖掉了，也没有办法把这些记录拿出来用。要做的是保留模型的输出、
   给一条结果标「不对」、一键导出（识别原文、模型输出、改成了什么、模型和提示词的版本），再配一个
   把导出文件变成检查用例的工具。数据留在本机，要不要发出来由用户自己决定。
   这是把「很差」变成能修的东西的唯一办法，排在这一段的第一位。
5. **用真机数据校准硬件配置表。** 显存门槛、CPU 档的线程数门槛、后处理默认开不开的门槛，现在是
   按模型大小和一台 Mac 的测速外推的。服务日志里已经有每次听写的耗时那一行，请测试者把日志发来
   就够了。需要 8 GB 和 12 GB 的 NVIDIA、AMD、Intel Arc、纯 CPU 至少各一台的数据。
6. **提示词跟着数据走。** Gemma-4-E2B 和 Mac 上的 MLX 各自量一遍，需要就各写一份（机制已经有了）；
   识别错的字（同音字、英文术语被听成别的词）要不要让后处理改，等第 4 项收来的例子再定——
   现在模型已经会顺手改一部分，但没有规矩，也没有检查。
7. **客户端的测试版更新通道。** 预发布版单独一份带签名的更新清单，加上设置里的「更新通道：正式 /
   测试」。版本号分开之后，服务端的改动测试者随时拉得到，这一项没有以前那么急；但同时动了两边的
   改动，仍然只能发了正式版才在别人的机器上暴露问题。

做完的标志：收到至少 50 条真实的「不对」并进了检查；配置表的每一档至少有一台真机的数据；测试者
能在设置里切到测试通道。

### 第三段：装得上，用得顺（12 月）

8. **没有 git 也能装。** 直接下载源码包；那样「更新服务」要另想办法。顺带处理境内访问 github.com
   慢时换镜像的问题（现在只能设环境变量 `VIF_REPO_URL`）。
9. **按应用自动选预设。** 现在预设要手动切。在聊天软件里用「聊天」、在邮件里用「邮件」、在终端和
   编辑器里用「技术」，其余用默认；对照表用户可以改。先做 macOS 和 Windows 上认前台应用。
10. **边说边看到字。** 服务端录音期间就在分段识别，并且已经把每一段的结果发了出来；两个手机端接了，
    桌面客户端没有显示。接到悬浮胶囊上：说长话时能看到前面的已经识别对了。
11. **Linux 说清楚支持到哪。** 托盘、Wayland 下的快捷键和输入，要么修，要么在文档里写明不支持。

做完的标志：一台没装过 git 的 Windows，从下载安装包到说出第一句话，全程不开终端。

### 第四段：手机（1 月）

12. **从「初版」到「能天天用」。** 维护者自己连续用两个星期，把用出来的问题清掉；Android 出正式版。
13. **iOS 怎么分发要有个决定**（见下面「要定的事」）。

做完的标志：手机端连续用两周没有丢字、没有连不上却不报错的情况。

## 要定的事

这几件不是技术问题，定了之后上面的顺序可能要变：

- **给谁用。** 如果目标是维护者自己和身边的人，上面的顺序是对的。如果要让不认识的人下载就能用，
  第三段要提前，而且得解决 Windows 安装包没有代码签名（SmartScreen 拦截）、macOS 没有公证这两件
  要花钱的事。
- **iOS 的分发。** 免费 Apple ID 签名 7 天过期，现在靠 `mobile/ios/renew.sh` 自动续，只适合自己用。
  给别人用要么付费开发者账号（每年 99 美元，走 TestFlight），要么验证 AltStore 能不能正确重签
  「应用 + 键盘扩展 + App Group」。
- **「不对」的样本出不出设备。** 现在的定位是数据不出自己的设备，所以第 4 项只做导出文件。
  要是愿意开一个自愿提交的渠道，收样本会快得多，但那是定位上的改变。

## 小一些的

- Whisper（transformers）自动检测语言时，结果里的语言一律报成 `en`。目前没有功能依赖它；
  做第 9 项（按应用选预设）或者以后按语言挑提示词时会碰到。
- 三个预设的「聊天」英文版在旧的 16 例检查上是 12 例合格（以前 15）；重调预设时一起看。

## 还没排期的想法

- 批量文件转写、说话人分离的界面（服务端已有 `/transcribe` 和 `/diarize` 接口）；
- 口述的编辑指令（「删掉上一句」「换行」）；
- 专业领域的词库、多人共享词表；
- 更多界面语言。

最早的路线图里还有云端识别 / 云端后处理和付费功能的设想。现在的定位是数据不出自己的设备，这些没有在做。
